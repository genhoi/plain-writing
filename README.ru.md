# plain-writing

**Одни правила для текстов, которые читают без нашего чата: задача в трекере, описание MR,
комментарий в ревью, отчёт.** Правила оформлены как скилл, его подключает любой агент. Скрипт
проверяет те правила, которые можно проверить. Остальное остаётся за человеком.

## Что это

Читатель открывает текст без чата, в котором он родился: разработчик другой команды, тестировщик,
лид через месяц, автор в новой сессии. Текст обязан работать сам по себе. Скилл говорит, что
выбрасывать (историю, внутренние коды, разделы «Не входит», самооценку), как обращаться с терминами
и фактами и какую форму принимают задача, описание MR, комментарий в ревью и отчёт. Полный текст в
[skill/SKILL.md](skill/SKILL.md). Перевод на английский: [docs/en/SKILL.md](docs/en/SKILL.md).

## Подключить к агенту

Склонировать репозиторий. Каждый скрипт можно запускать повторно: ничего не дублируется.

```bash
git clone https://github.com/genhoi/plain-writing.git ~/src/plain-writing
cd ~/src/plain-writing
```

**Claude Code.** Ссылка на `skill/` в `~/.claude/skills/plain-writing` и строка в
`~/.claude/CLAUDE.md`, если её там нет. Строка велит загружать скилл инструментом Skill, а не читать
файл: так Claude Code возвращает правила в контекст после его сжатия. С флагом `--copy` каталог
копируется, а не линкуется.

```bash
install/claude-code.sh
```

**Codex.** Строка в `~/.codex/AGENTS.md` с путём к `SKILL.md`.

```bash
install/codex.sh
```

**Любая среда с каталогом скиллов** (grok, kimi, Gemini, Codex через `~/.agents/skills`). Ссылка
на `skill/` в указанный каталог.

```bash
install/skills-dir.sh ~/.agents/skills
install/skills-dir.sh ~/.grok/skills
```

**Всё остальное** (zcode, веб-чат, свой системный промпт). Печатает скилл без служебной шапки для
вставки в системную инструкцию.

```bash
install/print-skill.sh
```

## Проверить текст

Python 3.11 или новее, только стандартная библиотека. На вход файл или stdin, на выход по строке
на замечание с номером строки и именем правила. Код возврата 1, если замечания есть, 2, если файл не прочитан.

```bash
python -m lint --kind task description.md
python -m lint --kind mr < mr.md
xclip -o | python -m lint
```

Вывод:

```
description.md:4: codes: «SHOP-410»: внутренний код без расшифровки: объяснить в том же абзаце или убрать
description.md:9: jargon: «fail-closed»: жаргон, замена: при сомнении отказывает
description.md:12: sections: раздел «Не входит»: убрать. Реальное ограничение идёт одним абзацем с причиной
```

Проверяется текст, а не разметка: по умолчанию Markdown, разметка Jira (`h2.`, пункты `#`, `{{имя}}`, `{code}`) тоже понимается.

| Правило | Что находит | Где список |
|---|---|---|
| `sections` | Заголовки «Не входит», «Что осталось за бортом», «Что не сделано», «Out of scope» и подобные | `lint/rules.py` |
| `jargon` | Кальки и жаргон, у каждого слова есть замена | `lint/jargon.txt` |
| `codes` | Ключи трекера вида `NP-12` (префикс проекта и номер), номера MR, имена веток рядом со словом «ветка» или «branch», если в том же абзаце нет пояснения. Не считаются: стандарты вроде UTF-8 или SHA-256; код-ссылка; код в скобках после утверждения («(NP-12)», «(задача NP-12)») и в строке «Closes NP-12»; код внутри пути в обратных кавычках | `lint/codes.txt` для кодов, `lint/rules.py` для веток |
| `self-praise` | «минимальный», «аккуратно», «честно», «очень полезно» и подобные | `lint/self-praise.txt` |
| `length` | Предложение длиннее 35 слов, абзац длиннее 8 предложений | `lint/rules.py` |
| `task-form` | При `--kind task`: разделы «Проблема», «Что сделать», «Как проверить»; в «Что сделать» нумерованный список, каждый пункт называет класс, таблицу или метод в обратных кавычках; в «Как проверить» нет классов, методов и тестов: раздел читает тестировщик | `lint/rules.py` |
| `mr-form` | При `--kind mr`: разделы «Зачем», «Что изменилось», «Проверки» (или «Как проверено») | `lint/rules.py` |

Списки слов: одна запись на строку, через табуляцию замена, затем при желании слова через
запятую, после которых совпадение не считается («минимальная сумма» не самооценка). Запись находит
слово и до трёх букв окончания: `минимальн` найдёт «минимальный» и «минимальные». Слово в кавычках
считается упоминанием и пропускается. Код считается объяснённым, если сразу за ним идёт скобка,
двоеточие, тире, «это» или «то есть». Блоки кода и строки HTML не проверяются.

**Чего линтер не делает.** Он не проверяет, правдиво ли утверждение о системе, и не находит
выдуманные термины. И то и другое остаётся за человеком, который публикует текст; правило есть в
`SKILL.md`.

## Тесты

```bash
pip install pytest
pytest
```

У каждого правила есть тест на срабатывание и тест на молчание. Примеры из `skill/reference/`
служат фикстурами: тексты «до» обязаны давать замечания, тексты «после» обязаны проходить. CI
делает то же на каждый push, а ещё прогоняет линтер по этому README и запускает каждый скрипт
подключения дважды.
